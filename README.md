# Руководство: Развертывание проекта «AI-Тимлид Макс»

 Документ содержит техническое описание архитектуры, системные требования и пошаговые инструкции по сборке, запуску и верификации функционала проекта в изолированном окружении Docker.

---

## 1. Паспорт проекта

* **Наименование проекта:** Образовательная программно-аппаратная платформа «AI-Тимлид Макс» (Web-сервис, Mini App и бот для мессенджера МАКС).
* **Команда разработчиков:** «Галактические боты».
* **Образовательная организация:** Муниципальное бюджетное образовательное учреждение дополнительного образования «Детско-юношеский центр космического образования «Галактика» города Калуги (МБОУДО ДЮЦКО «Галактика»).
* **Целевая аудитория:** Учащиеся IT-лабораторий, детских технопарков («Кванториум», «IT-Cube») и профильных инженерных классов в возрасте 10–17 лет.
* **Основная функциональность:**
  1. **Интеллектуальный Code Review 24/7:** Автоматический статический и семантический аудит исходного кода (JavaScript, TypeScript, Python, HTML/CSS, C++) с акцентом на безопасность, стиль и устранение синтаксических ошибок.
  2. **Сократовский метод наставничества:** Алгоритмы диалога направлены на формирование инженерного мышления: наставник не выдает готовый код для копирования, а указывает на контекст ошибки и задает наводящие вопросы.
  3. **Компьютерное зрение и аудит электросхем (IoT):** Анализ фотографий и схем монтажа на беспаечных макетных платах (Breadboard) для микроконтроллеров Arduino, ESP32, STM32 и Raspberry Pi Pico. Предотвращение деградации датчиков и риска коротких замыканий (контроль 5V vs 3.3V, общая шина GND, токоограничивающие резисторы).
  4. **Интерактивный симулятор Git:** Практический тренажер работы с системой контроля версий (git init, commit, branch, merge, push).
  5. **Дневник компетенций и геймификация:** Прозрачный учет решенных задач, начисление очков опыта (XP) и рост инженерного уровня.

## 2. Архитектура и стек технологий

Проект построен по модульной микросервисной архитектуре и упакован в два контейнера:

1. **Контейнер `webapp` (порт 3000):**
   * **Runtime:** Node.js 20 LTS (образ `node:20-alpine`).
   * **Серверный слой:** Express.js, TypeScript (`tsx`), прокси-контроллеры для нейросетевых моделей.
   * **Клиентский слой:** React 19, TypeScript, Tailwind CSS, Vite.
   * **Интерфейс:** Адаптивный дизайн Liquid Glass с поддержкой переключения тем оформления и мобильного разрешения.
2. **Контейнер `max-bot`:**
   * **Интеграция с платформой МАКС:** Официальная библиотека `@maxhub/max-bot-api` (взаимодействие с API `dev.max.ru` по протоколу Long Polling).
   * **Интеграция с Telegram:** Резервный модуль Telegram Bot API (с поддержкой кнопок WebApp).
   * **Отказоустойчивый Сократовский движок (`socraticEngine.mjs`):** Локальная экспертная база правил и статический парсер кода, обеспечивающие 100% доступность сервиса даже при отсутствии внешнего интернет-канала или исчерпании квот API.

## 3. Системные требования

* **Операционная система:** Любая ОС с поддержкой контейнеризации (Linux, Microsoft Windows 10/11 с WSL2, macOS).
* **Среда контейнеризации:** 
  * Docker Engine версии 20.10.0 или выше.
  * Docker Compose (v2) версии 2.20.0 или выше.
* **Сетевые порты:** Свободный локальный порт `3000` (при необходимости переопределяется через переменную `PORT`).
* **Доступ к сети Интернет:** Необходим при первой сборке (для загрузки базовых образов и npm-пакетов) и при обращении к внешним нейросетевым моделям.

## 4. Порядок развертывания через Docker Compose

### Шаг 1. Переход в каталог проекта
Откройте терминал (PowerShell / Bash) в корневом каталоге проекта:
```bash
cd /путь_к_проекту/max-teamlead-bot
```

### Шаг 2. Конфигурация файла переменных окружения (.env)
Создайте файл `.env` (их 2 штуки, 1 в папке bot/, другой в корневой папке) на основе предоставленного шаблона:
* В Windows:
  ```powershell
  copy .env.example .env
  ```
* В Linux / macOS:
  ```bash
  cp .env.example .env
  ```

Файл `.env` уже преднастроен со значениями по умолчанию. При необходимости укажите действующие токены:
```env
# Токен бота платформы МАКС (получен на https://dev.max.ru):
BOT_TOKEN="ваш_токен_макс"

# Токен бота Telegram (получен у @BotFather, опционально):
TELEGRAM_BOT_TOKEN="123456789:ABCdef..."

# Ключ Google Gemini API (опционально, при отсутствии работает локальный движок):
GEMINI_API_KEY="AIzaSy..."

# Публичный HTTPS-адрес веб-приложения для кнопки открытия Mini App в мессенджере:
WEBAPP_URL="https://ais-dev-uh6zjs2xamoeuueivmctfd-89586925952.europe-west1.run.app"

# Разрешение работы с TLS-сертификатами Национального УЦ (Минцифры РФ):
NODE_TLS_REJECT_UNAUTHORIZED=0

# Порт веб-сервера:
PORT=3000
```

> **Важное техническое примечание:**
> 1. Серверы мессенджера МАКС (`dev.max.ru`) используют SSL-сертификаты Минцифры РФ. Параметр `NODE_TLS_REJECT_UNAUTHORIZED=0` зафиксирован в конфигурации Docker, что исключает возникновение сетевых блокировок `UNABLE_TO_GET_ISSUER_CERT_LOCALLY`.
> 2. В кнопках типа `openApp` мессенджера МАКС платформа валидирует URL и требует протокол `https://`. По умолчанию в конфигурации указан валидный публичный HTTPS-эндпоинт.

### Шаг 3. Сборка и запуск контейнеров
Выполните сборку образов и запуск сервисов в фоновом режиме:
```bash
docker compose up --build -d
```

## 5. Проверка статуса и мониторинг сервисов

### Контроль состояния контейнеров
Для проверки статуса выполнения сервисов выполните команду:
```bash
docker compose ps
```
Оба сервиса (`max-teamlead-webapp` и `max-teamlead-bot`) должны находиться в статусе `Up`.

### Просмотр журналов событий (логирование)
* Просмотр журнала сообщений чат-бота:
  ```bash
  docker compose logs -f max-bot
  ```
  В журнале должно присутствовать подтверждение готовности:  
  `Бот для МАКС успешно запущен (платформа dev.max.ru)!`
* Просмотр журнала веб-сервера:
  ```bash
  docker compose logs -f webapp
  ```
  В журнале должно присутствовать подтверждение запуска:  
  `Сервер AI-Тимлида запущен на http://localhost:3000`
  *при возникновении проблем с подключением нейросети или других компонентов программы воспользуйтесь vpn

### Тест 1. Тестирование веб-интерфейса и Mini App
1. Откройте в браузере URL: `http://localhost:3000`.
2. Проверьте адаптивность интерфейса, переключение тем («Тёмное стекло», «Светлый фрост», «Киберпанк», «Изумруд»).
3. В разделе «Чат-наставник» отправьте вопрос:  
   *«У меня падает ошибка TypeError: Cannot read properties of undefined, как ее исправить?»*  
   *Ожидаемый результат:* Наставник применяет сократовский метод, анализирует контекст вызова объекта и задает наводящие вопросы без выдачи готового решения.

### Тест 2. Тестирование модуля аудита исходного кода (Code Review)
1. Перейдите во вкладку «Проверка кода».
2. Вставьте тестовый фрагмент JavaScript с синтаксической ошибкой:
   ```javascript
   const btn = document.querySelector('.submit-btn');
   btn.addEventListner('click', () => {
     console.log('Клик');
   });
   ```
3. Нажмите кнопку «Запустить аудит кода».  
   *Ожидаемый результат:* Сервис обнаруживает опечатку `addEventListner`, указывает номер строки, рассчитывает индекс качества кода и дает рекомендации по стандарту Clean Code.

### Тест 3. Тестирование схемотехнического модуля безопасности (IoT Lab)
1. Перейдите во вкладку «Электроника и схемы».
2. Выберите готовый демонстрационный сценарий (например: «Датчик DHT11 и питание 5V») или загрузите снимок макетной платы.
3. Нажмите кнопку «Проверить схему на ошибки».  
   *Ожидаемый результат:* Система фиксирует критический риск перенапряжения (подача 5V на чувствительный к напряжению сенсор), формирует чек-лист электробезопасности и выдает пошаговую схему безопасной коммутации на линию 3.3V с подтягивающим резистором.

### Тест 4. Тестирование чат-бота в мессенджере МАКС
1. Откройте приложение МАКС и перейдите в диалог с ботом команды по предоставленной ссылке.
2. Отправьте команду `/start`.  
   *Ожидаемый результат:* Бот отправляет структурированное меню с интерактивными кнопками вызова подсистем и кнопкой запуска Mini App.
3. Отправьте команду `/review` или отправьте текстовый фрагмент кода.  
   *Ожидаемый результат:* Бот возвращает разбор кода с кнопками дополнительных сократовских подсказок.

## 7. Отказоустойчивость и автономный режим

В проект заложен принцип **Graceful Degradation** (плавная деградация функционала):
* При отсутствии внешнего интернет-соединения, недоступности серверов Google Gemini или исчерпании лимитов запросов (HTTP 429 / 503) система автоматически переключается на встроенный движок `socraticEngine`.
* Все ключевые проверки кода, подсказки по микроэлектронике и диалоги наставника продолжают функционировать локально с нулевой задержкой.

## 8. Завершение работы с проектом

Для корректной остановки всех контейнеров проекта выполните:
```bash
docker compose down
```

Для полной пересборки с очисткой временных слоев:
```bash
docker compose down && docker compose up --build -d
```
